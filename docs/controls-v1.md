# JET SPRINT v0.18.0 — Analog controls and Xbox-compatible gamepads

## Integration boundary

Inspected the actual entry `index.html` → `src/main.js`, pointer/keyboard handlers, `physics.js` force integrator, existing Pit Control reparenting/range-reset components, settings envelopes, V8 start restrictions, race-start logical clock, cameras, campaign transitions and Pages workflow. This release replaces the real binary touch buttons; it does not add a second prototype or alternative unbound UI.

The only change inside `physics.js` is a finite, clamped signed `input.steering` adapter. Its previous left/right Boolean fallback and proportional throttle remain. No mass, thrust, pump, speed, acceleration, drag, yaw, drift, bank, current, course or handling defaults change. Full-lock analog and legacy commands produce identical boat states in regression tests. Throttle-dependent jet steering, coasting momentum and lack of dead-pump rudder authority remain. Main's pre-start rev path now passes the actual proportional throttle instead of reducing it to a Boolean.

## Input architecture

- `controls.js`: pointer capture and independent steering/throttle ownership; drag-anywhere rail geometry; safe-area/responsive placement; keyboard key sets; return/hold state; focus/orientation/cancel safety; controller polling and connected indicators.
- `control-input.js`: device arbitration, normalization/calibration, dead zones, curves, sensitivity, optional speed scaling, time-based smoothing and directional ramp limits. Reuses final `{steering, throttle, left, right}` commands; the legacy flags serve the navigator's throttle-to-steer hint. It has no boat-force calculations.
- `control-gamepad.js`: standard mapping, proportional button/axis-trigger profiles, neutral arming, hot-plug/loss, action edges/repeat, raw hardware diagnostics and optional rumble. Uses preallocated buffers. LT is deliberately unmapped because no brake/reverse physics exists.
- `gamepad-menu.js`: navigates the real visible controls, including ranges/selects, tabs, disclosure sections, existing dialogs and results. Text entry and browser file selection still need OS/browser input.
- `control-settings.js`: 42 input-only settings (35 numeric), validated defaults, three response presets, scoped resets, bounded JSON import/export and the stable `jet-sprint-controls-v1` schema-1 envelope. Missing v0/v1 fields acquire defaults; corrupt saved fields reset individually; invalid imports fail atomically.
- `control-lab.js` / `controls.css`: retained MARINE-87 components/tokens/fonts, collapsible groups, individual reset buttons, portable JSON, signals/curves and optional collapsed overlay. Touch thumb positions come from physical axes; diagnostics distinguish physical axes, filter targets and delivered commands. While Control Lab is open, a second instance of the same input processor previews live controller response and curves while the boat receives zero commands; this is input processing only, with no second physics model.

Most recent deliberate input owns the whole command pair; explicit priority prefers an engaged device and falls back otherwise. A neutral controller cannot interrupt touch. Handover clears the superseded device's ownership so an old held touch throttle cannot reopen when a newer key/controller returns to idle. Moving/pressing that device again requests ownership. Cancellation, capture loss, blur/backgrounding, restart, pause and tuning/results entry clear held axes immediately. Controllers must return to neutral after reconnecting or leaving a menu. Standard analog triggers use `button.value` with safe button/numeric fallbacks; legacy profiles accept a configurable RT axis and −1 or 0 rest convention. Unknown mappings cannot propel the boat until selected.

Arcade, Balanced and Simulation change input response only, retaining control layout, calibration, controller mapping and accessibility choices. Simulation uses touch Hold modes; cancelling or pausing still clears them. The current force/handling preset remains separate. Control JSON and resets never replace any existing physics, water, spray, audio, camera, graphics, race or campaign stores. Stable keys do not include a release/build hash; a normal same-origin deployment preserves values. Storage can still be cleared/blocked by the browser or user, so portable exports remain useful.

Menu/P/Escape pause freezes the existing logical clock and physics without changing boat state. A resumes/confirms, View cycles existing cameras, and Menu/B close setup or return through the pause menu. Opening Pit Control directly retains its original live-race behavior; opening it from Pause keeps the run paused. Browser Web Audio policy can require a trusted click/tap/key gesture even if a gamepad starts the race; the pause menu offers Enable / resume audio. The V8 DSP/audio modules are unchanged.

## Access and manual controller verification

Open **Pit Control → INPUT**, or **Pause → Control Lab / setup**. Groups: Steering, Throttle, Calibration, Controller, Input behavior. Every numeric control has a readout and individual reset; groups and the complete control configuration can be reset separately. Portable control JSON supports text, download and file import. Open **Live input / Raw → Command** or enable the optional collapsed on-course overlay to inspect signals.

For a physical Xbox-compatible controller:

1. Pair/connect using the OS, open the HTTPS Pages game (or localhost), focus it and press a controller button to expose it to the Gamepad API. Confirm the title LED/steering indicator reports connection.
2. Release RT and centre the stick. Use A to start, left stick X to steer and RT for proportional acceleration. Check small deflections, full lock, idle drift and throttle lift. LT should have no effect.
3. Use Menu to pause, D-pad to select Control Lab/setup, A to enter, D-pad to move through controls and left/right to tune values. Use B to return and View to cycle all cameras.
4. While driving, disconnect the controller or blur/background the page: commands must clear. Reconnect while holding RT: throttle must remain zero until RT/stick return to neutral. Repeat while opening/closing setup and pause.
5. Try both standard and any driver-specific trigger profile; check raw diagnostics. Test touch fallback, keyboard, custom priorities, presets, reset, JSON and reload. Enable haptics only on hardware/browser APIs that support them.
6. On physical iPhone Safari, test two real fingers, drag outside/capture release, long presses, rotation, safe areas/browser toolbars, Bluetooth, audio resume and sustained frame rate. Chromium viewport emulation cannot establish those results.

## Limits and publication

Physical Xbox/Bluetooth/USB hardware, real driver mappings/hot-plug behavior, haptics, iPhone Safari, subjective audio and sustained mobile frame rate are **not tested**. Gamepad support depends on browser/OS/security context. Play is controller-operable; text entry/file pickers and browser audio permission may need other input. Aggressive custom placements can cover scenery/instruments, but default layouts keep instruments and driving controls separated; hardware dimensions are bounded and overlapping touch regions are separated. Existing Three.js bundle-size advisory remains; no dependencies were added.

The existing Pages workflow still tests/builds/deploys, then downloads the actual published manifest and every asset and verifies the full commit plus SHA-256/lengths. This release also requires `controls: analog-input-v1` while retaining campaign/font/simulation identity checks. A local build or green build job alone is not proof of publication; check the deployment job's final **Verify actual published build and font files** step.
