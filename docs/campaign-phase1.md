Before editing, inspected course/track geometry, shared collision queries, force-based boat integration, ordered checkpoint crossings, navigation recovery, the logical race-start clock, rendering/water/scenery, independent spray, all tuning stores, and the existing Pages workflow.

The previous game generated one closed figure-eight at startup, assumed five laps in its race/HUD/results, and stopped/reset the boat when showing results. ## The playable slice

**Kōwhai Sprint Park** is a new fictional New Zealand inspired course, about 506 metres around three organic islands. Seven ordered race edges traverse the shared junction, hairpins and S-bends; 17 gates validate each lap. The staging inlet remains separate. The title's map is drawn from the actual course points. Course water is 18 m wide, retaining the original boat-clearance margin and force settings. Shore, water, terrain clipping, optional fluid bathymetry and collision all use the same network.

After **three valid laps**, the existing race timer freezes and the start state finishes. A real two-arm barrier swings open over about 0.8 seconds. Opening results is optional: the boat retains velocity, throttle and steering, and the navigator follows the course to the river outlet. The barrier is positioned beyond the junction's shared water and blocks swept crossings while closed/opening. Its cross-section is tested against every navigable line through the channel. No boat reset, teleport or loading transition occurs.

**Willow Run** is an approximately 184 m open spline river, 12.8 m wide, with a gentle downstream set opposing travel. Its world-space force does not write boat heading, nozzle or steering; throttle-dependent steering and lateral momentum remain in the original integrator. Seven ordered, forward-only checkpoints award bounded pace/clean-navigation points. Bank contacts remove the current leg's clean bonus. The optional side ramp has a central bypass, retains horizontal/angular momentum during a short gravity-driven hop and awards one landing bonus. Missed checkpoint cues direct the player behind the required gate.

**Mātai Basin** is a distinct oval preview basin with an island landmark, gold markers, dock and original signs. It remains a free-cruise placeholder; Track 2 racing is not implemented in Phase 1. The water/terrain/collision topology for the slice is available at startup. Five small preparation jobs create the destination's props during river travel and batch them into at most six material meshes. Bends, riparian trees, fog and distance culling manage sightlines. Prepared assets are reused across restarts and practice visits.

## Reusable boundaries

- `campaign-data.js`: serializable metre/second definitions, presentation coordinates, scoring/current/jump parameters, and the eight-track/seven-river graph. The remaining six main tracks and six river links are explicitly **planned**, with increasing current/difficulty and decreasing river widths; no unavailable geometry is presented as playable.
- `campaign-world.js`: reusable closed-course/open-river factories, route sampling/projection, shared variable-width water network, gate and checkpoint placement.
- `campaign.js`: rendering-independent race → exit → river → arrival state, gate collision, environmental current, bonus validation/scoring and optional flight. It accepts stage definitions instead of importing a particular track's rules.
- `campaign-scenery.js` / `campaign-ui.js`: Three.js presentation/preparation and the retained MARINE-87 UI integration. The first slice uses one bounded scene; a complete eight-zone paging/unloading system is future work.
- `campaign-progress.js`: separate versioned local milestones and per-stage best records. Practice shortcuts do not advance saved progress.

The existing force integrator changes only to accept a route-specific bank clearance. Default race water retains its original 6.5 m centre limit; the river uses the same 2.5 m safety margin. Course queries now index immutable segments in 16 m cells. At variable-width merges, they choose the greatest water clearance so a narrow tributary cannot create a false collision inside wider shared water. A brute-force oracle checks the optimized queries.

Millimetre-quantized capsule unions avoid sweep-line precision failures around tight bends. A graded, clipped floodplain avoids lifting nearly collinear terrain triangles into dark folds. The active ground has **2,076 triangles**, with a regression cap below 5,000; curved bank slopes, grass shading, vegetation and distant hills retain relief and detail. No square water slab or replacement shoreline cover is used.

Boat handling profiles, hull-motion springs, controls, V8 DSP/worklet/settings, four ordinary camera modes, typography/font files, design tokens, tuning-component handlers and the ballistic spray/wake modules are preserved. The camera's existing overview mode receives new world framing. Spray emission pauses while the hull is airborne; existing world-space drops continue under gravity, and landing creates a pooled foam disturbance.

## Persistence and diagnostics

Existing storage keys and versioned envelopes remain stable: game/physics/water/spray use `jet-sprint-settings` schema 3; audio uses `jet-sprint-v8-settings` schema 1; graphics uses `jet-sprint-summer-graphics-v1`; cameras use `jet-sprint-cameras-v1`. Their individual/category resets, named presets, JSON/file operations and page-hide flushes remain. Release metadata is not a storage namespace and does not reset values. Old five-lap score records remain readable alongside new records with `lapCount: 3`.

The new `jet-sprint-campaign-v1` envelope stores best race/river results and the Track 2 milestone independently. Reads validate values and add missing fields without touching tuning. Restart resets the run, not saved tunes or milestones. Same-origin deployments preserve localStorage; clearing site data or changing host is outside that guarantee. The dyno throttle remains a transient test input.

In `npm run dev`, open **Pit Control → RACE → Debug Tools → Campaign diagnostics / DEV**. It shows course, journey and race-start state, laps, gate position, checkpoints, streaming/preparation status, FPS, current boat state and results. Practice buttons reach the river or Track 2, explicitly mark practice and cannot unlock progress. This module, panel and shortcut API are removed by the production build. The production game's campaign inspector is read-only.

## Remaining limits

Physical iPhone Safari, sustained mobile FPS/thermal behavior, real-device Safari audio/gesture behavior and a human-driven complete race were **not tested**. Phone-sized Chromium layouts, software WebGL rendering and automated input are the available evidence. Low/Auto budgets remain, but acceptable sustained performance on a particular iPhone still needs device testing.

Track 2 has no race, and the other campaign stages have metadata only. The first slice prepares shared geometry at startup and destination props incrementally; it does not implement full eight-track asset streaming, economy, fuel stations, shops, podiums or controller changes. Water remains a level surface; the upstream current is an arcade environmental force, not a new hydrology solver. The short jump uses horizontal/angular inertia and vertical ballistics, not a full 3D rigid-body hull solver. Existing optional GPU diagnostic waves are not sampled for hull/spray contact. The large Three.js bundle remains a loading cost.
