# Persistent Garage & Career Foundation — v0.24.0

One existing boat now carries cash, fuel, condition and career progress between runs and application visits. The active three River Rush environments, boat/controls, countdown/timer, cameras, water/spray, V8 and tuning labs remain connected to their existing implementation. Archived circuit/campaign assets and logic remain available in the repository. No new course, second boat, cloud service or Unreal port was added.

## Player flow and presentation

Open **GARAGE / YOUR BOAT** from the title, **Pause → Garage / fuel & repairs**, or **RETURN TO GARAGE** from results. The native modal uses the established MARINE-87 fonts, cream/orange/teal/navy palette, tactile controls and safe-area spacing. The boat view clones the existing model's geometry/materials into a small lazy preview scene; it uses the same WebGL renderer/context. The preview has no physics/collision/wake and never moves the live boat. It respects reduced motion. Fuel/condition meters and services use accessible custom presentation and 44 px minimum buttons. Portrait/landscape garage content scrolls vertically without horizontal overflow.

Garage opening flushes the profile, releases input, pauses the live run and stops engine audio. Closing restores the previous pause/menu state. Cash, fuel, hull condition, service prices, emergency assistance, unlocked rivers and personal bests are visible. Engine, Waterjet and Hull categories are explicitly disabled future fit-outs: installed upgrades are an empty persisted list, and no upgrade purchases/effects are claimed. A compact fuel/hull row uses the existing racing HUD. New controls are reachable by keyboard, touch and the existing controller menu adapter; disabled course options are skipped by controller selection.

New careers begin with **$600, 100% fuel/condition and River Rush 1**. Valid finishes unlock River Rush 2, then 3. Existing players with restored settings or validated old progress retain all three rivers. Locked rivers remain available through explicit debug practice. Practice never earns money or official records; restarting a locked practice visit remains in practice.

## Canonical profile and persistence

`garage/profile-model.js` defines portable JSON and executable validation; `profile-store.js` is the local persistence adapter; `career.js` owns maintenance, service and reward transactions. The stable key is **`jet-sprint-player-profile-v1`**, `schemaVersion: 1`. It includes profile ID/revision, economy version, integer cash/lifetime earnings, one owned boat ID, 0–100 fuel/condition, installed upgrade IDs, unlocked/completed courses, revisioned PB/recent/completion records, bounded recent results and active/paid attempt sequences. [JSON Schema](schemas/player-profile-v1.schema.json).

The profile is the sole live career/cash authority. The preceding standalone `jet-sprint-river-runs-v1` PBs and old campaign wallet import **once**, with no retroactive reward. Old circuit result summaries are retained under profile extensions where validated. Original keys remain unchanged, including old settings, campaign and replay stores; an older open build cannot overwrite this new profile key. Release numbers do not select new defaults. Same-origin Pages updates retain saves. Changing origins, clearing browser data or private-session expiry can remove local data.

Fuel/damage save every three simulated engine seconds, at checkpoints, pause, garage, page hide and valid completion. Restart, level change, finish and reload never refill fuel or repair condition. Purchases and payouts require a successful profile commit before granting the service or changing cash. Failed writes retain pending resource changes and expose Retry/export; failed payouts remain pending in memory for retry, including while coasting after the finish. They are settled before issuing another paid attempt when saving becomes available. Closing a visit before unsaved data can be persisted can lose those pending changes. JSON backup export is available; replay and tuning backups remain separate.

Loading validates finite ranges, IDs, counters, bounded history/payload size and attempt relationships. Explicit v0 migration handles the documented pre-release field names. A previous validated profile is saved under `.backup`; unreadable primary content is quarantined under `.corrupt` where storage allows. Recovery uses the valid backup, then validated legacy data/defaults if necessary, and reports what happened. Unsupported newer schema versions open read-only and are not overwritten. A reload expires an unfinished payout attempt; its fuel/damage remains saved.

The synchronous local adapter checks observed revisions and blocks stale writes when another tab has advanced the profile. **localStorage does not provide atomic cross-tab/distributed compare-and-swap**. This is an offline prototype, with editable client data, not an authoritative shared economy or anti-cheat service. Future synchronization must authenticate a stable profile ID, validate commands, atomically check server revisions and enforce idempotency server-side.

## Fuel, damage and service balance

Engine-running use is based on elapsed simulation time, actual commanded throttle and a bounded speed/load term. Defaults are **0.008%/s idle + up to 0.055%/s throttle + up to 0.01%/s load**. A full tank supports several typical runs; even continuous full-load operation through the longest automated river run uses under 20%. Paused/hidden/garage/replay viewing does not consume fuel. Countdown revving and post-finish free driving do. The developer Audio Lab dyno remains maintenance-free.

Damage reads the existing bank/island/rock collision velocity impulse after real contact resolution. Below **3 m/s Δv** it is zero. Above that, a severity curve scales damage, capped at 12 percentage points per impact by default. A continuing contact charges only increases in the current peak severity; a 0.45 s contact-free gap starts a new impact. Gentle rubbing and repeated callback counts do not accumulate arbitrary damage.

At 30% condition and above, propulsion remains unchanged. Below that, power loss increases linearly to a modest **6% maximum** at zero condition. An empty tank retains **85% reserve propulsion**. The optional service multiplier affects jet translation/reported thrust, while existing nozzle response and steering torque remain active. Healthy service produces exactly the original force calculation. Empty/poor-condition boats can still navigate and race; resources never permanently disable participation. Reduced-service-power runs still record viewable world-pose replays but cannot replace competitive ghost PBs.

Refuelling costs **$2 per percentage point**; repair costs **$4**. The price button shows its actual destination percentage and cost, offering an affordable partial service if cash cannot cover a full one. A critical boat below 8% fuel or 15% condition, with insufficient cash to reach the basic service reserve, may request **free emergency assistance up to 20% fuel / 40% condition**. It does not reduce better existing values, grant cash, fully service the boat, or allow immediate repeated free full refills.

**HULL → Development / fuel & condition** contains ten numeric controls with readouts, units and resets: idle/throttle/load use, damage threshold/rate, impact release, maximum impact damage, low-condition threshold, maximum condition power loss and empty-tank reserve power. They save independently under `jet-sprint-maintenance-tuning-v1`, schema 1. Physics factory/custom presets, V8, water, input and camera stores remain unchanged. Current maintenance tuning also appears separately in the portable foundation export.

`CareerRiverProgress` adapts the original tour's persistence contract. `RiverRunTour` still accepts ordered directional checkpoints through the actual river leaf. Starting/restarting issues a durable increasing attempt sequence and invalidates older unfinished tokens. A payout requires the current known course/revision, full ordered checkpoint observations, sufficient actual simulation duration and the real final-gate time. Practice, stale/superseded tokens, duplicate completion callbacks, missing/out-of-order gates and implausibly short teleport completions cannot pay. The paid-sequence watermark remains after history truncation. Full valid repeat races earn the base prize; first-clear bonuses occur once, and a PB improvement must exceed 0.01 seconds. Clean bonuses use the existing contact cleanliness plus maintenance impact state.

Results show completion/PB and the actual finish/first-clear/improvement/clean breakdown. Valid completions update the profile's PB, bounded result history and next-river unlock together with cash. Viewing/importing a ghost, replaying the tape deck, restart and debug selection do not grant rewards. Old moving-entry river bonus times remain distinct from standalone rest-start times. Competitive replay records continue their independent course/force-tune grouping.

## Future Unreal/shared-profile boundary

Four data layers remain separate: player state/progression; boat physics parameters; course/route definitions; garage economy/maintenance/future-upgrade definitions. Profile JSON exports from the garage, numeric game definitions export from GHOST's existing portable-data tools, and replays retain their own format. The boat ID stays `sprint-boat-1987-v1`.

The [migration plan](UNREAL_MIGRATION.md) documents target SaveGame/`USTRUCT` import, stable-ID resolution, server revision/idempotency requirements and coordinate/units conversion. `docs/fixtures/physics-parity-v1.json` provides actual JS golden responses for healthy straight running, turn/coast, damaged power and empty reserve. `npm test` verifies these against the current integrator; `npm run export:physics-parity` deliberately regenerates them. A future Unreal runner can ingest the same inputs/settings and compare checkpoints. No Unreal importer, cloud sync or cross-engine parity result is implemented. JSON alone cannot guarantee identical physics.
