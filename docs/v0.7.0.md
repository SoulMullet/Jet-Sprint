# v0.7.0 — Waterjet handling and Crosswater navigation

This build implements all seven priorities in the next-build brief. The steering model uses pump thrust, nozzle deflection, yaw inertia and water resistance. Heading and velocity remain independent: releasing throttle removes powered steering after the pump decays, while the boat coasts and its existing yaw decays smoothly. Reapply throttle to recover a slide. Touch throttle remains the existing hold/release control; feather it to modulate thrust. The integrator also accepts fractional throttle values for future analog controls.

## Initial tuning

| Setting | Recommended initial value |
| --- | --- |
| Maximum speed | 85 km/h |
| Acceleration | 21 m/s² |
| Overall steering response | 75% |
| Nozzle authority | 30° |
| Pump response time constant | 0.12 s |
| Pump decay time constant | 0.16 s |
| Drift | 65% |
| Lateral resistance base | 8/s |
| Yaw damping base | 4.5/s |

Pump time constants are exponential: after three time constants the change is approximately 95% complete. Resistance is further scaled by drift and speed; these are arcade tuning values, not surveyed hull coefficients. The default pump loses roughly 95% of thrust in 0.48 s after release. Existing users' saved steering values, including the previous 85%, remain unchanged. Set steering response to 75% to try the recommended new baseline.

All 25 registered settings autosave and participate in named presets and portable JSON. Active settings advance to schema 2 through explicit schema-0 → 1 → 2 migrations. These preserve known values, unknown legacy backup data, and named presets; new handling IDs receive defaults. Keys remain independent of game version. No migration clears or rewrites leaderboard data.

## Course and navigation

The outer Emerald circuit is retained and connected to four interior channel segments meeting at a shared crossing. Smooth capsule unions produce one clipped water surface and matching bank rings; separate paths never acquire artificial closing bridges. Terrain clearance, collision, legacy depth shading and GPU bathymetry all use the same network. Bank markers are excluded from merged junction water. The existing scenery system and Bigfoot continue to use land clearance.

`course.js` separates the graph from an ordered closed route. Crosswater 1 visits both diagonals, several intersections, tight hairpins, the west chicane and sweeping outer channels. Its approximately 570 m lap has 114 finite-width directional gates, about 5 m apart. `Race` remains the sole checkpoint/lap authority, with five valid laps required. Unordered crossings, wrong-direction crossings and missed gates cannot award laps.

The navigator follows required gates rather than jumping to the nearest branch. Left/right, straight and sharp-turn cues include distance, close-turn previews, short transitions and recovery direction. Wrong-route detection has a short debounce; it leaves the timer running and requires returning to the missed gate. It never resets or teleports the boat. Instructions are plain data suitable for future voice callouts; no speech is implemented. A throttling tutorial hint has an eight-second cooldown.

The driver and navigator have separate helmets, life jackets, seated legs, arms and gloves. The driver sits at a steering wheel. Both are batched into the hull materials, share its transforms and bank, and keep the whole boat at six draw calls.

New results use course `emerald-network/crosswater-1` and gameplay version `0.7`. Older Emerald Loop records remain stored in their original groups; they are not compared against the new layout and handling. Settings changes never touch their storage key.

## Preservation and performance

The camera presentation block, countdown state machine/timestamps, Web Audio engine, touch input implementation, wake/spray code, Bigfoot code and all GPU solver/surface code are unchanged. The solver receives a new course mask, not new numerical passes or boat coupling. The next fluid simulation phase remains out of scope. Legacy water remains available. No new dependencies or external assets were added.

Rendering uses one union water mesh, one bank mesh, shared instanced markers and batched crew geometry. There are no simulation-grid tiles or debug overlays added to normal gameplay, no extra per-frame fluid readbacks and no new full-resolution simulation pass. Course generation and gate/cue construction occur at startup.

## Validation

- `npm test`: all 15 discovered test files pass. Coverage includes dead-pump stationary/moving steering, partial/full throttle, thrust decay, sliding/recovery, tuning extremes, 85/180 km/h convergence, graph connectivity, alternate-route geometry equivalence, five full prescribed laps, wrong-branch recovery, skipped gates, cue hysteresis/distance, crew transforms, additive settings migration and existing regressions.
- `npm run build`: passes; the existing Vite advisory about a JavaScript chunk above 500 kB remains.
- Chromium with SwiftShader: touch throttle during countdown revs audio without building pump thrust or moving the boat; green starts the clock and releases physics together; settings import/export/reload, wrong-route HUD, five-lap results, score-group preservation and restart are checked. Landscape/portrait and the central channel junction were visually inspected. Browser test hooks are injected externally and do not ship.
- GPU harness: existing float32/compensated-float16 conservation, wet/dry, obstacle, shock, reset and reference comparisons pass. The new course at 64²/128² remains positive and bounded for five simulated seconds after an impulse. Relative volume error was 5.81 × 10⁻⁹ / 2.93 × 10⁻¹⁰ respectively in software Chromium. These are numerical checks, not mobile performance measurements.
- Exact source comparison confirms the camera, effects, audio, Bigfoot, controls, countdown, GPU solver and surface implementations are retained.

Physical iPhone testing has not been performed. Handling still needs human tuning feedback; the physics is intentionally an arcade approximation. Dense gate validation allows normal movement within the navigable channel, including small corner cuts within gate width, but not skipped course sections. It does not attempt replay-based anti-cheat. Named presets and scores remain local to the browser; export JSON to back up tuning.

## iPhone Safari checklist

1. In portrait and landscape, hold throttle plus steering through READY/countdown/GO. Confirm revving, zero pre-start movement, immediate natural launch and readable lamps/arrows.
2. Compare steering while coasting with steering under power; feather throttle through the hairpins and recover a slide. Confirm comfortable control at 75% response and adjust if desired.
3. Follow every arrow through five laps. Take an outer alternative deliberately, confirm WRONG ROUTE and a running timer, return to the required gate, and finish/save/restart.
4. Check waves, shoreline junctions/islands, wake, rooster tail and both crew members while moving; provoke Bigfoot with the existing double tap.
5. Change the five new sliders, refresh, and try named presets plus JSON copy/paste, file import, download/share. Confirm older settings and scores remain available in storage.
6. Background/resume, rotate, test audio mute/volume and interrupted touches. Run several laps to assess sustained frame rate/temperature; compare Auto/Low and legacy water if needed.
