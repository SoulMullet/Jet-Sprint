# Arcade view and river sweep — v0.20.0

The existing v0.19.1 campaign remains the playable game. This release changes touch presentation, rendering cameras and phone orientation handling. Boat forces, courses, checkpoints, current, rewards/persistence, V8/audio settings and water/spray modules are retained.

## Controls and landscape

Active touch gameplay has LEFT/RIGHT at the lower left and THROTTLE at the lower right. Each button tracks an independent pointer set, captures contacts, paints a pressed state and immediately releases its command on pointer-up/cancellation. Opposite steering buttons cancel each other. No rudder force is introduced: the existing waterjet integrator still supplies steering from thrust.

`controls.js` retains the analog implementation behind an optional `arcade` adapter flag (off by default for existing callers/tests). Main enables it. Hidden analog DOM, layout/calibration/return settings, presets and code remain. The new digital branch applies only to touch commands; gamepad mappings, arm/disconnect logic, curves, dead zones, smoothing and stored configuration are unchanged. The existing controller source/settings files are unmodified. Numeric command processing for gamepad is compared against the retained pipeline in a new regression test; the original controller tests remain enabled.

The new stylesheet reuses MARINE-87 tokens and fonts with safe-area positioning, SVG arrow artwork and tactile orange throttle hardware. The existing HUD, navigator, starting lights and seven labs remain. Narrow landscape arrangements move navigation clear of the timer. Portrait coarse-pointer phones display a rotate prompt, release held controls and suspend boat integration/logical race time; no restart occurs. Safari can use physical rotation. Optional fullscreen/orientation lock is requested from a deliberate prompt-button click and failure is handled without blocking rotation.

## One final camera authority

`CampaignCameras` is the single final update in the existing animation loop. It reads boat/course/campaign state and never writes it. The prior `RacingCameras` controller is called only for explicitly selected legacy comparisons or overview, avoiding competing updates.

- **FLAT_TRACK_FIXED:** fits all racing-route points plus channel/shore margins at the chosen yaw/pitch/FOV and viewport aspect. Position/target remain stationary while racing. An auto-fit distance minimum keeps the course in view as offsets/FOV change; increasing distance pulls farther back. Orthographic scale is a developer framing override and can intentionally crop at values below one. A subtle optional boat ring and projected-size warning help when an entire larger course makes the boat small.
- **RIVER_TRANSITION:** begins on the existing campaign state change caused by a valid river-gate crossing. Merely finishing a race/opening its gate does not trigger it. The live boat/path feeds the destination throughout a default two-second sweep; position, target/rotation, FOV, projection and follow takeover interpolate. Duration is adjustable from 0.5–5 seconds. Repeated frames/crossings within the same river cannot duplicate the sweep. Arrival sweeps back to the destination course. Explicit restart/practice resets the camera for its new location; pause/orientation hold stops transition elapsed time.
- **RIVER_FOLLOW:** an elevated perspective boom with configurable angle, lag, limited heading rotation, river-tangent anticipation, lead, speed pullback and subtle bank. It uses the existing scenery obstruction query and conservative boom clearance. Sweep height provides clearance over low banks. This is practical avoidance rather than a guarantee against every hand-tuned camera/rock intersection.

Flat orthographic comparison uses a real orthographic camera. During a sweep, a homogeneous projection-matrix blend matches the orthographic focus plane to the perspective endpoint, avoiding a projection-type cut. The inverse matrix updates for the existing rendering/post pipeline. The same camera renders water/reflections; no new rendering pass is added. A single low-cost ground backdrop beneath the streamed land prevents empty rectangular tile silhouettes from appearing in broad views; actual channel/shore/collision geometry stays intact. Fog distance offsets account for the distant fixed viewpoint while retaining the graphics lab’s relative haze tune. Camera timing uses elapsed render time independently of the physics catch-up cap; single long stalls cap interpolation at 250 ms to avoid background catch-up jumps. Fit calculations cache until viewport/course/settings change; vector/matrix scratch space is reused during tracking/interpolation.

A preview invokes the camera sweep only, then returns to the current gameplay view. It does not pay rewards, cross gates or move the boat. Gameplay continues normally, so the race clock can naturally advance while previewing. Skip finishes the current sweep; interrupted previews/restarts safely restore the current course type. Legacy modes remain available via the original cycle button/Xbox View action; **Use automatic gameplay cameras** restores the primary manager.

## Camera Lab and saved settings

VIEW contains three collapsible sections. Flat controls cover yaw, pitch, distance, FOV, target/map offsets, target height, projection/scale, padding and visibility marker. River controls cover boom height/distance, downward angle/yaw offset, position/rotation lag, look-ahead, speed zoom enable/intensity, anticipation, bank/lag and target height. Transition controls cover duration, lift, arc, rotation/zoom timing, easing, takeover and focus. Every numeric control has a value/unit and individual reset. Auto-Fit, Test/Reset/Skip Transition and selected-course defaults are wired to the actual camera manager.

Each venue owns its flat camera, outgoing river and transition preset. The course dropdown edits that record; level debug selects the actual location for live preview. The independent **`jet-sprint-racing-cameras-v2`** schema-2 key preserves all older camera/controller/physics/graphics/audio stores. Changes autosave; JSON is validated/clamped. Copy/export, JSON download, text import and file import are available. Invalid imports preserve the existing configuration. Storage failure shows an export warning.

## Verification and limits

**195 tests pass on both Node.js 22 and 24; production build passes.** New automated camera tests frame all four courses at 844×390, 667×375, 1920×1080 and 1024×768 in both projections, verify stationary transforms as the boat moves, single gate takeover, two-second timing at 10/30/120 FPS, finite/smooth sweep steps, orthographic endpoint continuity, arrival/restart/practice behavior, preview/skip isolation, per-course persistence/reset/import and unchanged gamepad calculations. Existing complete seven-event input/physics, controller, water, spray, race timing, audio and campaign regression suites remain enabled.

The browser integration uses the actual main frame, manual animation clock and test-only controlled gate approaches. Repeated software-WebGL draws are suppressed between captures; screenshots are genuinely rendered. It verifies two simultaneous CDP touch contacts, independent immediate release/cancel, fixed camera transforms during driving, real three-lap finish/exit/sweep/follow with held keyboard input, per-course saves/reload and portrait state preservation. This is not a human-driven campaign or an FPS benchmark. Production is checked separately with the unmodified compiled entry, CDP touch and synthetic Gamepad API snapshots. Five landscape/tablet/desktop layouts (568×320 through 1920×1080) were measured without control/timer/navigation overlap, all four venue views were rendered, and an actual orthographic sweep preview rendered without page/shader errors.
